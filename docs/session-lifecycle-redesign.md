# 会话、连接与自动管理重构提案

状态：**方案已审定，按用户授权开始在独立分支实施，尚未部署**。本版按双方审查共识及用户拍板修订；DMS 主题检测已作为独立小修提交（`e7896ab`），主体完成情况以分支实现和验收为准。允许破坏旧的私有 IPC、Agent 协议及内部模块布局，不保留新旧协调流程双轨运行。实机事实与未通过项见 `session-lifecycle-experiments.md`。

## 1. 判断与范围

**判断：保留单所有者控制核心，替换混合的请求/连接/会话模型；合并 UI 与前端，收敛 Windows 会话路由。**

原则：每个概念必须保护真实的身份、授权或执行区别；不为想象中的扩展建设通用任务平台。减少用户需要处理的边界，不删除破坏性操作必须具有的授权边界。

本提案覆盖应用启动、RD/RemoteApp 切换、会话选择、交互确认、lock 和空闲生命周期。**不重新设计 virtio-mem 驱动、THP、balloon、managedsave、应用目录同步或凭据存储。** 不建设多 VM、多用户 RDS 调度或任意会话远程管理平台；但必须正确观察同一用户留下的多个登录，不能因为产品只管理一条连接就假设 Windows 只有一个会话。

## 2. 代码证据与裁剪

| 当前概念/证据 | 决定 | 替代职责及保留理由 |
|---|---|---|
| 控制器单所有者、FIFO、生命周期与 RPC 分离 | Keep | 保留业务顺序、外部观测和有界 I/O，不换成多管理器相互回调 |
| `Requirement=BackendOnly/Interactive/Desktop` 混合执行能力与连接模式；`session.go` 的 Desktop Dispatch 不执行应用 | Replace | 命令动作、执行位置和切换决定分别表达；桌面模式不再等于“应用已成功启动” |
| `switch-display` 强制改写原动作成 connect | Merge | 连接请求和应用请求共用一个执行流程，保留原始 payload |
| `SwitchDisplay` 特权布尔值和专用切换旁路 | Delete | 用已验证的明确动作决定转场；不再靠一个布尔值穿透普通请求规则 |
| 独立 dialog 可执行文件、嵌套 Go 模块和 DialogBinary 配置 | Merge | 最强保留理由是进程/GUI 隔离；目前工具链已经相同，发起请求的 CLI 自身承载短生命周期 GUI 即可，后台仍无 GUI |
| Windows SYSTEM backend 与用户上下文执行进程 | Keep | 权限、桌面环境、映射盘和 ShellExecute 的区别是真实边界，不能把启动应用搬到 Session 0 |
| 一个全局交互 TCP 端口代表任意用户会话 | Replace | 一个对宿主的后台入口，按明确登录身份路由到本机会话 worker；消除旧 agent 占端口和错误会话执行的风险 |
| inspect 按“唯一 Active，否则唯一用户会话”挑目标 | Replace | 返回完整受管用户会话快照，并绑定本项目实际连接；歧义必须可见，不能猜测 |
| lock 仅控制 VM suspend；测试明确允许 lock 后自动 StopDisplay | Replace | 在提交自动破坏性操作的统一入口约束断开、注销、缩容及挂起 |
| 因窗口/托盘为零而自动注销 | Replace | UI 计数是活动观测，不是注销授权。注销还必须有明确目标与相应授权 |
| VM 来源重连、安全内存准备、业务副作用不自动重放 | Keep | 这些保护实际状态和数据安全，不能为了统一流程而删掉 |

## 3. 收敛后的职责

```text
发起命令的 CLI（GUI / TTY / 显式选项）
          ⇅ 一个持续请求，确认消息与结果
宿主控制器（一个状态所有者、一个业务 FIFO）
  ├─ 已观测状态、请求推进、授权与 lock 检查
  ├─ 自己持有的 FreeRDP 连接
  ├─ libvirt / 内存适配器
  └─ 一个 Windows 后台入口
             ├─ WTS 会话观察、登录身份校验、注销
             └─ 按 SessionRef 路由至用户会话 worker
                    ├─ ShellExecute / 应用目录 / 映射盘
                    └─ UI 活动观测
```

Windows 的 RemoteApp shell 保活仍只在 RemoteApp 路径需要；它不再同时承担全局用户请求入口。用户 worker 与保活可复用同一二进制的内部运行角色，但不能让“保活进程存活”冒充“目标会话可执行请求”。

不新增独立的 SessionManager、LifecycleManager、DialogManager 进程，也不引入通用工作流引擎、事务数据库或业务重放队列。

## 4. 最少但不能合并的状态

### 4.1 三种实际对象

- **VM**：已确认的 libvirt 状态、来源是否可信、启动代次。
- **Connection**：本控制器拥有的 FreeRDP 实例、连接代次、请求的 RD/RemoteApp 模式、实际绑定的 SessionRef、就绪/失效状态。
- **Windows 登录**：SessionRef、账户 SID、显示名称、WTS 连接状态及已知活动。**SessionRef = Session ID + AuthenticationId（token LUID）+ BootIdentifier**；SID 单独校验账户归属，LogonTime 只作辅助校验和诊断，不充当登录身份。拿不到有效实例身份就保持 Unknown，不降级为仅 Session ID。BootIdentifier 跨冷启动及休眠/恢复的行为仍待验证；不预设休眠必定改变它，不以随校时推算的 LastBootUpTime 替代。

RD/RemoteApp 是本次连接的属性，不是 Windows Session ID 永久固定的类型。FreeRDP 进程存在、WTS Active、用户 worker 就绪分别证明不同事实，不合成一个模糊的 Ready。

### 4.2 一个请求

请求保留原始业务动作和参数，并将**执行环境（`UserContext bool`）与目标显示模式（可选 `Mode`）正交分离**：
- `UserContext` 标识该操作是否必须在用户会话内部执行（用户 token、profile、用户级映射盘与 ShellExecute）。
- 可选 `Mode` 表示请求偏好的特定显示连接形式（如 `ModeDesktop` 或 `ModeRemoteApp`）。

两类请求路由策略不同：
1. **通用用户环境请求（`apps`、`sync-apps`、`mounts`）**：
   - 设定 `UserContext = true`，**不包含 `Mode` 属性（Mode 留空）**。
   - 若当前已有绑定的活动显示连接（无论当前处于 RD 桌面还是 RemoteApp 模式），**直接复用当前已绑定连接对应的用户 worker**，不提示、不触发模式切换；
   - 若当前没有活动显示连接（`!Display`），则默认启动 RemoteApp 连接以建立会话；
   - **绝对禁止猜测并拾取保留在后台的断开登录（Disconnected login）**：由于不同登录会话所加载的网络映射盘（`net use`、`\\tsclient` 等）及会话私有状态可能互不相同，随意拾取断开的旧登录执行会导致读写错误的映射环境或破坏会话隔离。
2. **特定应用启动请求（`run`、`open`）**：
   - 具有特定模式倾向（默认 RemoteApp）。
   - 若当前处于已绑定的桌面连接（Desktop），**即使桌面为空，也须明确选择（含“在当前桌面执行” `current`、保留、注销或取消；已传入有效 `--on-conflict` 时不再弹窗）**，把是否在全屏桌面内直接拉起应用的选择权明确交由用户裁决。

用户在确认时只表达一个互斥动作：
1. 在已绑定的当前桌面登录中执行（`current`）。
2. 保留已识别的旧登录，连接目标模式后执行（`keep`）。
3. 注销明确识别的旧登录，连接目标模式后执行（`logoff`）。
4. 取消（`cancel`）。

不继续使用 `--reconnect=yes/no` 与 `--logoff=yes/no` 的笛卡尔组合。CLI 最终可以用一个明确的冲突处置选项对应上述动作，但选项名不是内部模型，先落定动作语义。无冲突时照常执行；显式要求的动作若无意义或前提不成立，要报错，不能静默忽略。

## 5. 连接与 Windows 会话必须真正绑定

后台提供受配置账户约束的完整会话快照，使用 SID 区分本机/域同名账户。允许正常的单用户多登录观察，但不自动清理用户所有登录。

FreeRDP 使用稳定的、最多 15 字符的短 ASCII `/client-hostname`，不随进程更换；连接代次只在宿主记录。本机实测换新 hostname 会尝试新建登录并失败，恢复原标识即可重连，因此不能把随机 hostname 当连接代次。标识只是关联信息，不是认证秘密；访问控制沿用现状，不新增 ACL、对端 PID/映像校验或认证框架。

**客户端主机名迁移与升级注意事项**：
- 新版本中 FreeRDP 的 `/client-hostname` 默认配置为 `"rdp-launcher"`。旧版未显式设置该参数，实际名称由旧 FreeRDP 及其参数决定，不能直接等同于 `os.Hostname()`。
- 本机已有“保留旧登录后换名首连失败”的对照证据。升级保留旧断开登录时直接换成默认 `"rdp-launcher"` 存在复用失败风险；实验曾记录 `CsrConnected` 转换错误 `0x80004005`，但不能据此断言所有 Windows 策略下都如此。
- **升级前必须由用户二选一进行处理**：
  1. 用户先保存工作，通过 Windows 正常注销旧图形登录；不要为迁移自动调用已知有故障的旧注销 RPC；或
  2. 在 `config.toml` 的 `[freerdp]` 中将 `client_hostname` 显式配置为旧版实际生效的主机名（控制器不自动假定为 `os.Hostname()`，必须由用户明确配置）。
- **实机验收边界**：现有实验记录证明了“更换 tag 标识且保留旧登录会导致会话复用失败”（different tag + retained old login failure），但**尚未覆盖从旧默认主机名平滑升级到新默认主机名的完整实机验收**；该特定升级路径的完整验收仍标记为 pending（待真机验证）。当前业务 VM 已关机，不进行意外的开机或后台注销操作。

WTS 事件和初始订阅快照只触发异步刷新。只有新鲜完整快照同时确认 Active、稳定 hostname、配置账户 SID、有效 SessionRef，并能唯一关联本控制器正在建立的连接，才能绑定；用户 worker 还须按该 SessionRef 就绪才可派发。**不能硬等新的 logon 事件：实测重连只有 connect/unlock。connect 或 logon 任一通知本身也不等于 Ready。**

FreeRDP 启动前先取得新鲜会话基线，启动后只接受基线中没有的新登录，或 ConnectTime 已变化的同一登录；旧连接残留的 Active 状态不能让新进程提前绑定。过渡期旧、新登录同时 Active 时先排除未变化的基线登录，再判断候选是否唯一；同登录重连仍允许，不永久排除旧 SessionRef。

断开后 WTS 的 ClientName/地址会清空；控制器保留此前确认的绑定，不事后从清空字段重建。绑定失败时，不自动注销重试，禁用无法确定目标的派发和转场步骤并说明原因；不退回解析日志、进程名或“唯一 Active 就是我的”。

完整会话查询在控制器之外异步执行，通知回调只发刷新信号；查询设截止时间、限制在途数量，不能把一次原生调用卡住扩散为控制器或状态订阅阻塞。快照带代次、采样时间和新鲜/过期/Unknown 状态；相关连接变化、来源丢失或查询超时使旧快照失效。旧快照只供展示，不用于新的派发或注销；晚到结果不得复活已失效的代次。

未绑定时可以展示候选和错误，但不能把应用派发或注销到推测出来的登录。外部登录与本控制器创建的连接不自动等价。

Windows 用户 worker 通过后台按需创建/注册并绑定 SessionRef，不给所有历史登录预先常驻一套进程。宿主只调用后台入口；后台通过沿用现有权限机制的本机通道与相应用户 worker 通信，不增加新的安全验证层。必须保留正确的用户 token、环境、用户配置文件和桌面上下文，不能在 SYSTEM 中直接调用 ShellExecute。

后台只启动固定的自有 worker，不扩展成任意 SYSTEM 命令/路径/脚本执行接口。现有窗口/托盘 probe 逻辑合并进 worker 的观察能力，不再独立维护临时文件回传协议；应用业务也不能因为 worker 缺失而退回在 SYSTEM 中执行。

### 5.1 注销是 Windows Agent 的操作

宿主仍只提交带目标 SessionRef 和授权的注销操作；**Agent 在 Session 0 的 SYSTEM 上下文中执行系统 `logoff.exe`**，不经 SSH，也不启动用户会话 worker 来注销。

```text
核对新鲜的 SessionRef、账户 SID、授权与操作准入
→ 用独立子进程执行 %SystemRoot%\System32\logoff.exe <Session ID>
→ 有界等待，记录退出码与诊断
→ 刷新登录状态，确认原 SessionRef 已消失
→ 向宿主报告结果
```

- 固定系统程序路径，Session ID 作为独立数字参数，不通过 shell 拼接命令，不扩展成通用命令执行接口。
- 子进程与 Agent 具有相同的 SYSTEM / Session 0 上下文，不额外提升或启用权限。本机实测 Active RD 与 Disconnected RemoteApp 两种目标均成功，分别约 682ms、437ms；后台 PID 不变、ping 正常。过期目标在启动命令前被拒绝，详见实验记录 §6.2。
- 执行命令前紧接着重新核对 SessionRef，尽量缩短校验与执行之间的窗口。`logoff.exe` 只接受 Session ID，这段时间内仍可能发生登录结束和 ID 复用，无法保证完全消除竞态；按本项目风险可控、不增加复杂防护的口径接受这一边界。事后发现同一 Session ID 已对应新的 SessionRef 时，报告异常，不追加操作。
- 不能只凭退出码 0 宣称注销完成；注销可能异步结束，须在操作剩余期限内有界轮询，确认原 SessionRef 消失。期限到达仍未消失或查询失败时，按未确认/结果未知处理。
- 命令等待上限 30 秒（Agent 侧超时预算为 30 秒），并受操作剩余期限约束；后续确认不重新获得一整段操作期限。超时、断线或确认失败时不自动重试，不宣称杀掉子进程就能撤销已经提交的注销；继续必要的状态确认。宿主外层（Host outer）调用注销操作的超时预算设置为 35 秒，为网络传输与通信留出 5 秒余量，避免外层过早放弃等待而导致状态失步。
- 采用这一替代策略，不继续用旧的进程内直接注销路径作失败兜底。旧 `0xC0000005` 的根因仍独立核实，不要求先定位旧根因才能实现替代方案；但命令成功不等于 Agent 集成已验收，前后的身份查询、结果确认和异常路径也必须验证，不能只替换一行调用就视为完成。

## 6. 一个流程覆盖启动、切换与确认

```text
入队 → 获取所需的可信观测 → 确定目标与可用动作
     → 必要时等待调用方选择
     → 复核目标/连接与授权
     → 执行必要转场 → 确认新连接与 worker
     → 执行原应用请求一次 → 返回结果
```

- 当前桌面执行：不停止 FreeRDP，不注销，直接使用已绑定登录的 worker。
- 保留切换：只断开自己的旧连接，再建立目标连接并重新绑定。**当前环境实测，同一 hostname 下 RD 与 RemoteApp 分别进入 Session 4/6，旧登录与新登录并存**，会继续占用内存并影响空闲回收。不能许诺跨模式沿用同一登录或自动迁移旧应用；也不把本机行为硬编码成所有 Windows 的通则，每次仍核对实际 SessionRef。
- 注销切换：只注销用户授权的具体登录并确认结束，再完成旧客户端清理及新连接。不注销所有同名用户的登录。使用 §5.1 的 Agent 系统命令实现，替代故障路径；完成 Agent 内集成及隔离验收后才接入该动作，按用户决定，不单独先修或禁用生产旧注销 RPC；在本次重构中统一替换。
- 删除现有切换流程中因 `windows==0 && tray==0` 而触发的 `require_empty` 自动注销分支：空登录默认保留，不能把活动计数当作注销授权。显式注销选择与自动空闲注销是不同授权来源。
- 未选择、取消、关闭 UI 或请求断开：不开始新的破坏性步骤，保持原连接。
- 已接受的注销、启动和 VM RPC 不能假装因取消而撤回。完成观测和必要安全收尾，向调用者说明已经发生或结果未知；不自动重放业务动作。
- 转场失败时不发送应用请求。启动成功只承诺对应 API 已接受，不伪造“应用窗口已显示”。

### CLI 与确认协议

- 由发起命令的 CLI 直接调用 UI，不提供 dialog 子命令或再次 exec 同一二进制的隐蔽入口。
- 能连接 Wayland 时使用现有 MyGo UI；没有可用 Wayland 连接但有 TTY 时，使用同样的动作与警告；无两者时 stderr 给出明确选项要求，非零退出。
- 控制器发出确认消息，包含本次任务、具体目标与当前允许动作；CLI 只能回复选择，不能自行决定可以注销哪个会话。
- 同一个 FIFO 任务和 IPC 连接保留到选择/取消/超时。确认等待上限 **60 秒**，并受调用方剩余总期限约束；到期取消、释放队头，不更动原连接。确认回复与该任务和相关会话快照绑定，断线只取消本任务；不做“先查再重投”的两次请求。
- `status`、`lock`、`unlock` 不等待确认队头；本地 `version/help/list-apps/path` 直接处理。`ping` 可能唤醒 VM，`apps/sync-apps/mounts` 可能需要远端用户环境，仍走业务 FIFO，不能另设越队执行器。确认等待不会无限阻塞后续目录同步。
- 期间状态/lock/SSH/来源事件照常处理。相关登录、连接或权限变化使确认失效，重新确认或明确失败；内存样本变化不应让无关确认失效。
- GUI 与终端共用动作模型，不把安全规则写到视图内。多文件 open 一次选择作为一个有序批次，失败时报告已执行部分，不为后续每个文件重复弹窗或重新授权。
- DMS 主题检测独立先修：从 `$XDG_RUNTIME_DIR/dms-<PID>.session` 确认 display 等于当前 `WAYLAND_DISPLAY`，核对文件名中的父进程及 `.pid` 中的 qs 进程仍存在，并在总计 200ms 的 socket 探测预算内确认对应 `.sock` 可连接。不启动 `dms` CLI。残留配置/缓存/运行文件都不能单独启用主题；未运行、检测失败或超时回退系统主题。GUI 创建时重新判断，TTY/无界面路径不探测。高对比度、减少透明度偏好仍优先；迁移时连同 `dms.go`、主题/无障碍逻辑及测试一起带入，不只搬 main.go。MyGo 实测支持链接后不初始化 GUI 的无界面路径，现有 dialog 可交叉构建 Windows；不预先规定必须加 build tag，仅在实际平台依赖需要时做最小隔离。

## 7. lock：统一禁止自动资源回收，而非冻结控制器

建议用户语义：**lock 后维持当前使用状态，不因空闲自动动连接、会话或 VM；显式用户请求仍执行。**

| 行为 | lock 后 |
|---|---|
| 状态订阅、会话检测、记录进程自然退出 | 继续 |
| 用户明确发出的启动、断开、切换、授权注销 | 允许，仍校验身份与确认 |
| 空闲自动停止/重新建立 FreeRDP | 禁止 |
| 空闲自动注销图形登录 | 禁止 |
| 挂起前主动内存回收 | 禁止 |
| 空闲自动挂起/关闭 VM | 禁止 |
| 无需暂停 VM 的压力保护性扩容 | 继续；与空闲回收区分 |
| 为内存初始化而自动暂停/恢复 VM | 不偷偷穿透 lock；未准备好时说明阻塞原因，等待显式流程 |
| 已接受操作的状态确认、必要安全收尾 | 必须继续，不伪造撤销 |

实现上不在每个分支散落 `if locked`。所有可改变连接/会话/VM 的步骤提交前，通过同一个操作准入点，携带明确来源：用户请求、自动空闲计划或既有操作的安全收尾。来源不能从 `job == nil` 推测，因为内存准备也会是 nil job，而用户触发的策略性注销未必已获授权。

lock 到达时取消尚未提交的自动步骤与空闲 deadline；后续重新检查准入。若内存初始化的 pause 已被接受，则完成必要的 PrepareMemory / 安全 resume，作为已有操作的安全收尾，不把 VM 留在不安全的中间态；lock 禁止的是开启新的自动初始化暂停周期。已经送达 Windows/libvirt 的 RPC 是无法消除的边界：继续核实结果并报告，不能承诺绝对零竞态。unlock 从新的观测开始重新计时，不补执行过期动作。

**lock 只存在服务进程内存中，不持久化，不创建 management.json。** 保留 VM 关机清除 lock 的现有行为，服务重启也回到 unlocked；这是用户选择的生命周期，不承诺跨重启维持锁定。它不阻止用户显式退出控制器，也不保证控制器崩溃后 RDP 一定存活；这不是连接接管/高可用机制。

## 8. 自动空闲流程不是另一套执行器

空闲策略只产生一个受权限限制的任务，复用同一个身份解析、步骤提交与结果确认路径：

保留现有两段计时，不改变挂起计时起点。连接期间，RemoteApp 可以由窗口空闲触发断开；RD 不套窗口计数，通常由用户关闭连接。**显示断开（`!Display`）后，注销与挂起使用同一个计时起点**，同时沿用 SSH、lock、来源有效性等既有空闲准入条件，无论断开是自动触发还是用户关闭：

```text
RemoteApp 窗口空闲 → idle_disconnect_timeout → 断开
RD 用户关闭 ────────────────────────────→ 断开
                                          ↓
                          断开后计时 → idle_logoff_timeout：可选注销，确认后立即回收
                                    → vm_suspend_timeout：挂起并确认
```

- 新配置 `lifecycle.idle_logoff_timeout`，单位秒，**默认 -1 表示禁用**，不再增加 `idle_session_action` 或其他注销开关。启用时为非负值；若挂起已启用，则要求 `0 <= idle_logoff_timeout <= vm_suspend_timeout`；若挂起禁用，则不设此上界。小于 -1、越界或时长溢出均拒绝。
- `idle_logoff_timeout=0` 表示断开后立即尝试注销，不表示禁用。`idle_disconnect_timeout` 和 `vm_suspend_timeout` 的 0 仍保留各自禁用的既有含义；注销不依赖自动断开是否启用，手动关闭 RD 或 RemoteApp 后也适用。
- 超时表示步骤可以开始的时间，不是强制完成期限。注销超时为 0 时先完成断开，再校验和注销；等于挂起超时时仍先完成注销、确认和回收，再挂起，不并发抢跑。
- 启用注销时，内存回收移到**确认注销完成后立即执行**，不再等到挂起前；禁用时维持现有挂起前回收时机。回收有界、报告 actual；等待挂起期间出现新业务/压力/lock，仍按准入规则处理，不为守住时间点继续缩容。
- **空闲注销倒计时与内存状态的独立性**：注销计时器（`idle_logoff_timeout`）完全不受内存压力（pressure）、内存扩容中（Growing）或内存状态未知（unknown memory）的影响；这些内存状态仅作为安全内存回收（reclaim）和 VM 挂起（suspend）的门控条件，绝不重置或延长注销倒计时。
- **确认注销后的回收安全暂存**：当注销确认完成后，若当前内存状态不满足安全缩容条件（如处于 Growing 或压力状态），待执行的内存回收会被安全暂存（held until safety allows），待内存条件允许后再执行。
- **待注销期间禁止提前缩容**：在已启用的空闲注销仍处于待处理（pending）期间，绝不在挂起前执行提前内存缩容（no pre-suspend shrink while enabled logout still pending），避免在注销未决时产生无谓的内存收缩甚至引发来宾端抖动。
- **断开至 WTS Active 的过渡态处理与外层超时预算**：
  - 当 FreeRDP 显示断开后，Windows 端的 WTS 状态可能暂时仍呈现 `Active`（属于断开过渡期，Disconnect -> WTS Active transitional state）。
  - 控制器不得盲目将其视作外部已接管会话或立即注销，更不得原地自旋或提前挂起 VM。
  - 处理机制：立即废弃本地会话缓存（invalidate cache），发起新鲜查询（fresh inspect），并以 **500ms 间隔持续复核，最长等待 30 秒**。
  - 若在 30 秒内会话正常转为 Disconnected，则继续推进正常的注销与空闲流程；
  - 若复核确认连接客户端（ClientName/Address）或连接发生实质改变（即真实的外部客户端 Active 登录/接管），则判定为外部活动，跳过自动注销，保留该登录并报告原因；
  - 在该过渡态决议未决（pending resolution）期间，控制器绝不自旋忙等，也绝不抢先执行挂起；
  - 宿主外层（Host outer）注销超时预算设定为 **35 秒**，包容 Agent 端 **30 秒** 的系统命令执行与确认预算。
- 注销候选只限本轮空闲流程当前或最后一个自持连接已确认绑定的 SessionRef；不得扫描注销同名用户所有登录，也不顺带清理其他保留登录。用户选择“保留旧会话”不能被新流程偷偷改成注销。
- 超时启用是对该受限自动行为的配置授权，不把一次“注销并切换”的授权扩展到未来登录。目标身份和活动须新鲜且符合允许条件，窗口为零不等于所有进程都可杀。
- 禁用注销、无合格目标或安全条件不能确认时，仅跳过注销并报告保留的登录数，不因这一项阻断其他仍符合条件的断开/回收/挂起。未发生或失败的注销不算完成回收；仍符合挂起条件时按既有规则在挂起前安全回收。关键来源丢失等会独立阻止后续操作，不能借“跳过注销”绕过。
- 新请求、相关活动、SSH 非零或 Unknown、关键观测丢失或 lock 使空闲计划不再成立时，不再提交后续破坏性步骤。无法撤回已接受的副作用，保留实际状态继续报告。自动空闲计划是可中断的后台推进，不得占住 FIFO 队头拒绝新业务入队；新业务先使其失效，再等必要的在途确认/安全收尾结束。
- Niri 窗口计数可以触发 RemoteApp 空闲检查，不能证明 Windows 登录为空；RD 不能套用 RemoteApp 窗口数判空。
- 回收目标被接受与 actual 已下降是不同结果；不宣称此重构能保证碎片化 Windows 将全部内存归还宿主。

## 9. 必须暴露和必须隐藏的边界

用户只需处理三类情况：**选择如何处理旧会话、无法确认操作对象、操作失败/结果未知。**

端口、worker 生命周期、窗口探测 helper、FIFO 及重连退避都封装在实现内部。边界错误由协议明确区分，不能全部压成字符串或一个 Ready：至少区分需要用户选择、目标已变化、当前能力不可用、失败和副作用结果未知。

不得隐藏：注销的数据损失风险、外部会话不归本控制器所有、已提交操作无法可靠撤销，以及“窗口/托盘不可见”不等于会话无工作。

每次副作用记录统一任务 ID、来源、目标登录/连接、原因、接受结果与确认结果。status 只保留可读输出，展示 lock、当前绑定、快照新旧状态、当前阶段、最近错误、阻塞原因及保留登录数；**删除 `status --json`，不加 schema_version，不做旧 JSON 字段映射或消费者迁移**。宿主内部 IPC 是否用 JSON 与此无关。避免再出现只有 FreeRDP 日志，却无法回答控制器为何挂起、注销或拒绝应用的情况。

## 10. 落地顺序与验收

1. **先集成已验证的注销替代策略，并验收执行通路。** 现有 `logoff_session` 的 `0xC0000005` 根因仍另行核实；新 Agent 按 §5.1 使用 SYSTEM / Session 0 子进程执行系统 `logoff.exe`，不以旧进程内调用作兜底。临时 SYSTEM 任务已验证两种目标状态，但仍需在隔离 Agent/临时登录中验收请求校验、前后查询、命令执行和结果确认；通过后才接入注销切换与自动注销。旧根因未定位不再单独阻塞替代方案，也不自行禁用现有生产入口。当前源码切换时自动空会话注销与显式“注销并切换”共用旧 RPC；日常空闲目前仅 StopDisplay。其余验证覆盖 RD/RemoteApp、两个断开登录、重连、登录 ID 复用、启动实例身份及同名账户；未通过前不接入破坏性操作。
2. 替换会话快照及 Windows 路由；保留旧 ShellExecute/目录/映射盘实现，不保留全局交互端口作为兼容兜底。
3. 替换请求模型和 FIFO 推进，贯通原业务 payload；实现一次请求内的确认通信和取消语义。
4. 合并 GUI 模块到 CLI，删除 dialog 二进制、配置及部署路径；同一动作模型实现 GUI/TTY/stderr。
5. 接入统一自动操作准入和新 lock 语义，再用同一路径替换空闲清理。删除原来 `TestLockOnlyBlocksVMSuspend` 所固定的旧行为。
6. 协议版本不匹配立即拒绝并提示“请配套升级”，不静默忽略新字段。继续手动更新，不设计 SSH 部署、回滚流程或长期新旧协议兼容。

### 用户可感知的迁移变化

- 切换时删除基于 windows/tray 为零的自动注销，空登录默认保留；手动注销必须明确选择，等待 Agent 的系统命令实现集成验收，不再依赖故障路径。
- 日常空闲注销默认禁用（-1），与现在日常空闲仅断开的行为一致；启用后才在指定时间注销并立即回收内存。
- 保留原有两段计时：RemoteApp 空闲断开 30 秒，再等挂起 300 秒，名义总等待仍约 330 秒；RD 手动关闭后才开始挂起计时。新增注销超时与挂起超时一样从断开后起算，不改变既有挂起语义。
- lock 的抑制范围扩大，但不持久化，VM 关机清锁行为不变；保留 `TestUnlockStartsNewTimerAndVMOffClearsLock` 的关机断言，只替换 `TestLockOnlyBlocksVMSuspend`。
- 移除 dialog 二进制/配置，发起命令的 CLI 自己显示 UI；删除 `status --json`，仅保留可读状态。
- 手动配套更新宿主与来宾，版本不匹配明确拒绝；不增加更新器或兼容兜底。

验收至少覆盖：

- 桌面内打开确实在已绑定桌面执行，既不重连，也不返回空成功。
- 跨模式的四个动作行为一致；取消和过期确认不改变原连接。
- 已知错误/过期/不明确的 SessionRef 在提交操作前被拒绝。注销前最后一次校验与命令执行之间的 ID 复用竞态仍按 §5.1 承认，不以测试声称完全消除。
- Agent 在 SYSTEM / Session 0 下通过系统命令注销 Active RD、Disconnected RemoteApp，前后身份确认正确且后台保持可用；覆盖命令非零退出、超时、IPC 断线、异步退出后才确认完成、退出 0 但期限内未确认、查询失败、事后发现 Session ID 复用，均不误报成功或自动重放；发现新 SessionRef 时只报告异常，不追加操作。
- lock 后无自动断开、注销、缩容、挂起；显式操作仍可执行。unlock 重新计时；VM 关机清锁，服务重启不恢复 lock，不产生持久锁文件。
- 空闲注销默认 -1 禁用，0 为断开后立即；与挂起同起点，等于挂起超时时按断开→注销确认→回收→挂起排序。覆盖 RD 手动关闭、RemoteApp 自动/手动断开、自动断开禁用、挂起禁用及越界配置；原有两段计时不变。新请求、lock 及活动打断后不补执行旧 deadline。启用时确认注销后立即回收，禁用时保留挂起前回收。
- 等待确认时收到会话重新连接、来源丢失、lock 或新请求，行为有确定测试；新请求不越过正在等待用户决定的业务 FIFO 队头，但可以中断自动空闲计划。
- 自动挂起前仍检查 SSH；用户请求不被旧空闲计划插队。
- 多文件打开只确认一次，已执行部分不重复派发。
- DMS 已退出但配置/缓存/运行文件残留、父/qs PID 不存在、display 不匹配、socket 不通时使用系统主题；运行且数据有效时才应用 DMS。探测预算有界，不运行 dms CLI；TTY/无界面路径不做 DMS 探测。
- 确认最多 60 秒且受请求总期限约束；超时释放队头且原连接不变，status/lock/unlock 不被阻塞，需远端工作的 FIFO 命令不越队。
- 请求超时、CLI 退出、RPC 已接受但来源丢失都不重放启动/注销。
- 可读 status 覆盖关键状态，`status --json` 不再接受；新旧协议不匹配提示配套升级。
- 断开至 WTS Active 的过渡态以 500ms 间隔复核至多 30 秒，外部活动跳过注销；宿主外层 35 秒超时与 Agent 30 秒注销预算协同，不提前抢跑挂起。
- **实机必验：自持连接断开前后，WTS ConnectTime 保持不变。** 分别记录 RD 手动关闭、RemoteApp 自动/手动断开的绑定值、过渡快照和 Disconnected 快照，同时保留 SessionRef。当前实现把 ConnectTime 改变视为另一连接重连；若 Windows 在单纯断开时也改写它，会安全地保留登录，但可能每轮错误跳过空闲注销，并产生误导性的重连原因。必须实测确认，不以单元测试或原实验结论代替；若不成立，再调整判断及日志。**2026-10-23 本机三种断开均已通过，重连正向对照也通过**，见 [实测记录与原始证据](connecttime-validation.md)；不推广为所有 Windows 策略的保证。
- 不依赖正在运行的真实 VM 的大多数状态机与协议测试；真实验收使用独立测试端点和临时测试登录。

- Windows 原生 WTS 调用本身无法通用地中断；超时后不接受晚到快照，不在已过期身份检查后启动新的业务命令。管道取消需等待 I/O 完成后才能释放 OVERLAPPED/缓冲区，极端驱动不完成取消时仍可能超过清理期限；不能为形式上的超时释放仍被内核使用的内存。

## 11. 暂不加入的东西

不加通用策略语言、插件化会话后端、可恢复业务事务、用户可操作的内部 dialog 命令、多个布尔开关组合出来的注销授权、全机所有登录自动扫除、日志解析式会话绑定，以及为了掩盖 Windows 内存碎片而无限重复回收。
