# Go 宿主控制器架构

## 1. 目标与范围

将 Linux 宿主迁移为 Go 实现的事件驱动控制器，而不是逐模块翻译现有 Rust 代码。Windows 端继续使用 Rust，按职责拆分后台能力与 RemoteApp 交互能力。

部署环境保证一个 Windows VM、一个宿主 RDP 会话。多个 CLI 请求可以进入同一会话。本文不引入多 VM 调度或多会话管理。

本轮先实现可用的端到端流程。Windows 后台最终采用 Windows Service 还是用户常驻进程，留待流程可用后测试并确认，不作为当前实现的前置条件。实现时保留后台与交互端的职责边界，不依赖某一种最终安装方式。

本文是 Go 迁移的架构入口。Rust 仓库 `/code/rust/rdp-launcher` 中的 `docs/host-controller-architecture.md` 和现有源码作为迁移参考；本文记录本轮已确认的修正。旧实现的业务表现不作为新控制器的正确性标准。

## 2. 总体结构

```text
Linux
  CLI 请求 ─────────────────────┐
  Niri 窗口消息 ────────────────┤
  libvirt 生命周期消息 ────────┤
  Windows 后台状态 ────────────┼─→ 宿主控制器主循环
  FreeRDP 进程退出 ────────────┤       ├─ 业务 FIFO
  外部操作完成 ────────────────┤       ├─ 生命周期状态
  倒计时到期 ──────────────────┘       ├─ 活动状态与 deadline
                                       └─ 自动暂停许可

Windows
  常驻后台：后台请求、SSH 观测与通知
  交互端：RemoteApp 保活、依赖交互用户环境的操作
```

宿主主循环独占业务状态。消息源负责采集和预处理，操作执行路径负责阻塞 I/O，结果通过消息返回主循环。

Windows 两个角色可以复用同一 Rust 工程或可执行文件的不同运行入口。具体进程组织和安装方式在实现与测试后确认。

## 3. 主循环与操作执行

主循环持有：

- VM 的已知状态及正在进行的控制操作。
- Windows 后台、FreeRDP 和交互端的就绪状态。
- 业务 FIFO、队头请求及其执行阶段。
- RemoteApp 窗口活动、SSH 零/非零状态。
- 显示空闲 deadline、VM 暂停 deadline。
- 自动暂停许可。

执行方式：

```text
接收消息
   ↓
更新状态
   ↓
按当前状态选择下一项操作
   ↓
提交外部操作，继续接收消息
   ↓
操作完成消息推进后续阶段
```

TCP 请求、libvirt RPC、应用扫描及子进程等待不阻塞主循环。等待 VM 恢复或远端请求返回时，主循环继续处理生命周期、活动和后续 CLI 请求。

内存 I/O 可以与 UI 启动或远端请求并行，避免慢请求堵住内存压力响应。VM 变更仍串行。控制器分别取消各操作，并在退出前等待有界清理完成。

消息源可以维护解析所需的局部状态，例如 Niri 窗口集合；业务决策归主循环。操作执行路径不自行修改主循环状态。

## 4. 消息源

### 4.1 Niri

订阅窗口事件，先建立窗口快照，再按窗口 ID 更新集合。预处理识别 FreeRDP RemoteApp 窗口并报告活动变化。

- 窗口从非零变为零：进入显示空闲判断。
- 窗口从零变为非零：取消显示空闲计时。
- 断线：窗口观测失效。
- 重连：重新建立快照。

窗口状态是显示空闲的依据；FreeRDP 进程退出用于连接状态和资源清理。

### 4.2 libvirt

通过 `digitalocean/go-libvirt` 注册生命周期事件，按目标 domain 过滤，区分启动、恢复、暂停、关闭等变化。注册成功后才启动控制器，先建立事件订阅，再通过串行 VM 控制路径查询初始状态。复用库的 RPC、认证和事件解码，不解析 virsh 文本。

主循环在选择后续 VM 控制操作前，优先应用已到达的生命周期与来源就绪消息。断线立即使 VM 状态为 Unknown；重连先确认订阅，再要求 QueryVM 补齐断线期间的状态，快照完成前不执行新 VM 控制。Unknown 会中止正在进行的内存准备，旧操作结果不能恢复该准备。VM 恢复使旧空闲计时失效，VM 关闭结束本次运行状态。

控制 RPC 与事件订阅使用独立连接。取消一次 RPC 不关闭生命周期订阅。当前接入本地 Unix socket；socket 路径与驱动 URI 由调用方显式提供。

### 4.3 Windows 后台

后台使用长 TCP 连接提供状态：建立订阅时发送一次快照，之后仅发送状态变化。连接结束或报错使后台与 SSH 观测失效。

主循环向后台来源报告 VM 状态变化。Running 时建立新的订阅并取得快照；暂停、关闭等状态结束旧订阅。初始 VM 查询完成后才开始订阅，避免丢弃初始化快照。

长连接没有应用层心跳或固定读取超时，连接故障检测交给 TCP。静默网络故障的发现速度取决于系统 TCP keepalive，而不是本项目的定时消息。SSH 观测的具体机制见第 7 节。

### 4.4 FreeRDP

宿主持有自己启动的 FreeRDP 子进程，等待退出并报告消息。进程存在、交互端就绪和后台可用分别表达，不互相替代。

控制器启动时如何接管已存在的唯一显示连接，在可用流程实现后测试确认；不为此建设多会话归属系统。

### 4.5 来源生命周期

每个来源负责自己的连接、初始化、读取、重连与收尾。来源断线不能被解释为无活动，也不取消整个控制器及其 FreeRDP 根 context。断线时对应观测失效，失败重连使用 100ms 至 5s 的可取消退避。内存订阅确认后重新 QueryMemory；重连只清除连接丢失错误，不清除驱动、协议、写入或恢复安全错误。停止时关闭连接、回收相关子进程并结束读取任务。

## 5. 宿主业务 FIFO 与就绪条件

业务请求由 CLI 提交给宿主控制器，按宿主接收并入队的顺序推进。请求入队时更新业务活动与倒计时状态。

队头按能力需求等待，而不是一律建立 FreeRDP：

| 请求需求 | 就绪条件 |
|---|---|
| 仅后台 | VM Running，Windows 后台可用 |
| 需要交互 | 上述条件，以及 FreeRDP 和交互端就绪 |

```text
请求入队
   ↓
队头等待 VM Running 和后台可用
   ↓
按需等待 FreeRDP、交互端就绪
   ↓
执行队头请求
   ↓
回复请求方，推进下一项
```

等待条件是主循环中的执行阶段，不是从头阻塞到尾的 ensure 函数。后续业务请求保留在队列中，生命周期与活动消息继续处理。

run/open 属于交互请求。应用派发调用返回后推进下一项，不等待应用退出或文件关闭。

sync-apps、mounts 等能力是否能够仅通过后台完成，要结合用户环境的实际可访问性验证。无窗口不等于不依赖用户上下文；不为了分类而提前确定 Windows 服务部署模型。

SSH、生命周期、连接状态等观测消息不进入业务 FIFO，不受队头等待或慢业务阻塞。

宿主负责业务排序。Windows 端执行已经派发的请求，现有派发机制的保留或调整以实际需要为准。

## 6. Windows 后台与交互端

### 常驻后台

- 启动不依赖 FreeRDP。
- FreeRDP 断开后继续提供后台能力。
- 负责 SSH 观测和状态通知。
- 处理不依赖交互显示的请求。

后台进程自身存活不计作业务活动，否则 VM 将永远无法自动暂停。

### 交互端

- 承担 RemoteApp 保活。
- 执行需要交互用户桌面和用户环境的操作。
- 与常驻后台具有独立的就绪和退出状态。

现有 Rust 实现的 ShellExecute、快捷方式扫描、图标提取、用户映射盘查询等能力优先复用。它们的运行位置取决于所需用户上下文，不直接搬入系统服务并假设行为不变。

先验证后台与交互端协作的可用流程，再确认 Windows Service 或用户常驻进程的安装、自启动和会话行为。

## 7. SSH：零/非零边界通知与检查兜底

项目只需要判断 SSH 活动是否为零。宿主保存三种观测状态：零、非零、Unknown，不需要维护精确连接数。

Windows 侧利用连接事件识别零/非零边界，并通过现有 TCP 表检查确认：

- 零 → 非零：check 确认后通知宿主，取消 VM 暂停计时。
- 非零 → 零：check 确认后通知宿主，重新判断 VM 空闲条件并开始计时。
- 非零范围内的数量变化，例如 1 → 2：不向宿主发布业务状态变化。

初始化、事件观测异常及低频兜底使用现有检查。检查失败表示 Unknown，不能转换成零。后台连接失效时，宿主也将 SSH 观测设为 Unknown。

保留现有观测语义：guest 本地 SSH 端口上的已建立 TCP 连接，不将其改称为经过认证的 SSH 登录会话。

当前实现使用 `ferrisetw` 订阅 `Microsoft-Windows-Kernel-Network` 的 IPv4/IPv6 accept 与 disconnect 事件。事件只触发一次 TCP 表检查，不直接对连接数量加减。首次检查与 60 秒低频检查保留，发布内容只有零/非零/Unknown 的变化。

ETW 需要相应权限；启动失败时记录原因并使用低频检查。事件模式在 win11 的 SYSTEM 后台进程中验证通过：IPv4 和 IPv6 均可在约一秒内报告边界变化，1 → 2 → 1 不产生业务状态通知。约一秒延迟来自 ETW 缓冲刷新，不是每秒轮询 TCP 表。

## 8. VM 控制与自动策略

### 串行 VM 控制

VM 查询、启动、恢复和暂停共用串行控制路径。已有调用返回后，主循环应用已到达的生命周期消息，再决定下一项控制操作。

命令返回与状态确认分开：

- `QueryVM` 返回一次状态快照；期间已收到的生命周期变化优先于旧快照。
- 启动、恢复、PM 唤醒命令成功，仅表示请求被接受；目标确认状态为 Running。
- 暂停命令成功，仅表示请求被接受；目标确认状态为 Paused。
- 主循环同时收到命令成功与目标状态后，才释放当前控制操作。生命周期事件可以先于命令结果到达。
- 等待确认时继续处理其他消息，但不提交下一项操作，也不重复发送控制命令。
- 确认超时直接报告错误，将 VM 状态设为 Unknown；不轮询 domstate，也不重发命令。后续新请求可重新查询状态。

libvirt 生命周期事件没有本项目的操作 ID。确认依据是目标 domain 与目标状态，而不是伪造事件和请求之间的 ID 对应。显示进程退出、普通操作结果仍使用宿主操作 ID 关联。

### 显示空闲

无 RemoteApp 窗口时开始显示空闲计时。窗口重新出现或业务活动使旧计时失效时，取消或重置计时。

到期后根据当前状态决定是否断开 FreeRDP。显示断开不停止 Windows 常驻后台。

### VM 空闲

无交互连接、无待处理业务、SSH 确认为零，并且允许自动暂停时，开始 VM 暂停计时。

新请求、SSH 活动、观测失效或生命周期变化使空闲条件不成立时，取消计时。到期消息按当前状态验证，旧 deadline 不得暂停新的活动流程。

### lock / unlock

lock 关闭自动 VM 暂停许可，unlock 开放许可。它们不停止控制器、消息源或业务 FIFO，也不替代显示空闲策略。

锁状态保存在控制器内存中，VM 关闭后本次运行的锁状态失效。

## 9. 内存控制范围

内存控制已接入，默认需显式启用。宿主按 Windows 物理占用率的 95%/80% 双阈值扩容，目标向上对齐 128 MiB。Agent 只采集和通知，不保存阈值。

回收固定在 suspend 截止前 30 秒开始。到期允许 partial reclaim，保留实际值后暂停，不等待无限收敛。Unknown 不当作零。

内存控制复用串行 VM 控制路径和 QEMU 事件订阅。已接入暂停阶段的地址窗口准备，以及有实际进展才追加的有界续处理。详见 [自动内存控制](memory.md)。

## 10. 迁移与验证

### 当前落实范围

已实现 `internal/controller/` 控制核心：主循环、业务 FIFO、两种就绪条件、操作完成消息、生命周期确认、活动 deadline 和自动暂停许可。

已实现 `internal/adapter/`：

- `libvirt.go`：复用 `digitalocean/go-libvirt` 查询和控制 VM，订阅生命周期消息。
- `niri.go`：使用标准库 net/encoding/json 接入所需的三个窗口事件，不建设完整 Niri SDK。
- `agent.go`：对接 Rust Agent 请求协议与后台 `watch_status` 长连接。收到初始化快照或变化后更新后台与 SSH 状态；不通过 status 轮询或心跳刷新。
- `freerdp.go`：启动和回收所拥有的 FreeRDP 子进程，通过 stdin 提供凭据并报告退出。当前用有界的交互 Agent status 及会话激活状态等待协议就绪，不声称能确认 RAIL 窗口出现。
- `session.go`：组装控制器与来源，复用 errgroup 管理生命周期。后台与交互端使用独立 endpoint，派发前选择其中一个，不双发请求。VM 状态变化驱动后台重新订阅。

Windows Rust Agent 已复制到 `windows-agent/`。同一可执行文件有 backend 和 interactive 两个入口；daemon 是 interactive 的兼容别名。后台负责 SSH 与状态订阅，不创建窗口或启动 GUI；交互端复用应用扫描、图标、映射盘与 ShellExecute 等能力，不承担 SSH 观测。

宿主 CLI 使用 TOML 配置，通过用户 Unix socket 向同一常驻控制器提交请求。配置兼容 server、freerdp、remoteapp、lifecycle、mounts 和 overrides 相关字段；凭据复用系统 Keyring。guest IP 显式配置，不做自动地址发现。Niri 使用 NIRI_SOCKET，可不接入，此时窗口状态保持 Unknown。入口用法见根目录 README。

VM 状态驱动后台重订阅。单次初始连接尝试最多等待一分钟，失败后来源继续退避重连，允许 Windows 后台晚于 VM Running 启动，不因此结束 Session。libvirt 与内存来源重连均先确认订阅，再要求控制器重新查询。执行器负责一次业务操作及其 context 取消；业务失败回复调用方，不禁止后续空闲管理，也不重放远端副作用。

已在 win11 验证后台独立运行、SSH 事件边界、交互端请求、实际 RemoteApp 文档窗口和无心跳长连接。Go 主循环也通过真实 libvirt 与新后台完成仅后台请求。自动回收、暂停、恢复与重新订阅已完成真实验证。Go 宿主 CLI 到 FreeRDP、交互端的 run/open、应用同步、图标与桌面导出和映射盘查询已通过真实环境验证。完整冷启动与最终 Windows 部署方式尚未验收。迁移结果见 [Windows 验证记录](windows-validation.md)，本轮结果见 [内存验证记录](memory-validation.md)。

### 实现原则

- 复用底层交互契约，不照搬旧业务协调结构。
- 移除旧会话文件锁、活动 revision 和事件唤醒后全量重查的协调方式。
- 将超时、协议边界、子进程清理等必要处理集中在交互边界。
- 保留配置、凭据、应用导出、路径和挂载等产品能力；兼容细节按实现需要明确。

### 底层互验证

使用 Rust 作为 Agent 协议、virsh/Niri 解析、FreeRDP 参数、Keyring、路径转换和桌面导出的对照。存在已知问题的行为不作为必须兼容的结果。

有副作用的 run/open 不双发对照；远端请求超时不自动等同于未执行，也不直接重试启动命令。

### 控制器验证

以确定的消息序列验证：

- 两种就绪条件按请求需求推进。
- 并发请求保持 FIFO，复用同一次唤醒和连接过程。
- 等待外部操作时仍处理生命周期与活动消息。
- 新活动使旧 deadline 失效。
- SSH 零/非零转换和 Unknown 正确影响暂停计时。
- FreeRDP 断开不使后台能力消失。
- 失败和过期结果不错误推进后续流程。

### 真实环境确认

基础流程可用后，测试冷启动、暂停恢复、后台独立请求、交互请求、显示断开后的 SSH 观测，以及 apps/open/mounts 所需的用户环境。

在这些结果基础上，确认 Windows 后台最终部署方式和启动策略。代码量与测试工作分别评估，不使用开发者天数作为迁移依据。
