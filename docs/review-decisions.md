# 审查处理决定

本文先于本轮修复编写，随后按 reviewer 的核实意见细化验收条件。它区分需要修复的问题与保留的实现边界；“不采用”不是延期承诺。下文六项并不意味着 reviewer 曾建议相反方案：ConnectClose、内存安全暂停、不重放业务请求及不做崩溃事务原子性，均与 reviewer 的建议或澄清一致。验收以代码和回归测试为准，不能用基线测试通过代替故障路径验证。

## 本轮修复范围

1. 请求失败不得设置自动生命周期熔断；只有无关联请求的自动操作失败才停止自动重试。取消与业务错误分别回归测试。固定边界：请求关联的 StopDisplay 失败后，允许恰好一次无请求关联的自动 StopDisplay；这次也失败后必须停止，不能无限重试。
2. 来源断线只使对应观测失效。后台、Niri、libvirt 生命周期和内存事件来源自行退避重连。冷启动超过一分钟不得关闭控制器。业务 RPC 不自动重放。生命周期断线必须报告 VMUnknown；重连先完成订阅确认，再设置 needQuery，重新 QueryVM，不能沿用丢失事件之前的状态。内存断线使 DeviceKnown=false；重连确认后重新 QueryMemory，只清除连接丢失产生的特定错误，不清除驱动、写入或安全错误。必须测试 VMUnknown 发生于内存准备期间会中止该准备，旧结果不能复活准备状态。
3. 两个 Windows TCP 端点增加共享 token 校验，覆盖所有动作，包括 Quit 和状态订阅。远端只持有 token 文件；宿主从 Keyring 读取。非 loopback 监听不得静默降级为无鉴权。token 文件须同时允许 SYSTEM 与配置的交互用户读取，不能向其他本地用户授予读取权限，验收检查 ACL 及两个身份的读取路径。明文 TCP 仍仅用于受控网络，不宣称提供加密或公网安全。
4. socket 旁的持久锁文件使用 flock(LOCK_EX|LOCK_NB)，覆盖探测、清理、监听及整个 serve 生命周期；拿不到锁就不处理现存路径。锁文件不能 unlink，进程死亡由内核释放锁。获得锁后仅恢复确认失效的 Unix socket，连接超时、权限错误或其他不确定错误不得触发删除。并发启动测试必须证明只有一个控制器持有监听器；更新 README 中“不另建会话锁”的旧说明，保留“不使用 PID 文件”。
5. 内存恢复失败继续保持 Paused；补充 status 的可操作错误和人工恢复说明，不提供不校验安全目标的强制恢复。
6. 显式校验请求完成与 FIFO 队头的对应关系，避免将隐藏约束留给未来维护者。
7. 应用同步先准备产物，成功后发布并最后提交缓存；处理可报告的发布失败，清理自有 PNG。多文件发布不宣称具备掉电事务原子性。
8. 拒绝空 overrides.match、含 CR/LF 的密码。XML 单位乘法不加溢出分支；reviewer 已撤回该项，代码仅注释实际输入和支持规模的前提，不列为审查发现的缺陷。普通 libvirt 连接关闭策略不改变，理由见下文。
9. 保留主模块与 GUI 的工具链隔离，但提供涵盖两个模块的检查入口，避免只检查根目录就误称全仓库通过。

## 明确不采用的改法

### 不因 Run 的内层 break 而连续启动所有可执行操作

审查指出的是潜在延迟，不是已证明的饥饿路径。当前 next() 在选中请求前先检查可执行的内存工作；启动 UI 后，新观测和内存期限会再次唤醒主循环。已有 TestControllerMemoryIOIsNotBlockedByDispatchAndDoesNotCancelIt 验证真实 Run 中的重叠，不只是直接调用状态机。

不把这个 break 改为无条件排空调度。现有两个工作槽已经限定允许的并发，不应为未经证明的吞吐问题增加调度路径。本决定不宣称并行是对称的：内存先启动时仍会阻止新 UI 操作，VM 变更仍独占控制槽。这是当前的顺序约束，而不是“所有 I/O 都并行”的承诺。

如未来出现稳定复现的到期操作无法调度，应凭该复现修改调度；这不是当前预留的待办。

### 不把 GUI 的 go 声明降低到 1.24 或 1.26

固定依赖 github.com/egoist/mygo v0.5.5 自身要求 Go 1.27.1。仅改 go.mod 声明不能提供旧工具链支持。把整个 CLI 一起升级，又会让不使用 GUI 的宿主承担同样要求。

保留独立模块及显式 GUI 构建命令。Go 1.26 + GOTOOLCHAIN=local 不能构建整个产品，是实际支持边界，不是已解决的问题。统一检查入口必须检查 GUI，不能将 go test ./... 描述为覆盖嵌套模块。若产品要求单一 Go 1.26 工具链，就必须另行更换 GUI 依赖；本文没有承诺这样的兼容性。

### 不给每次 libvirt RPC 增加无期限 ConnectClose

操作各自拥有连接，取消时关闭底层 socket，用来中止在途 RPC，避免后台遗留调用。固定版本 go-libvirt 在 socket 断开后会清理事件流和回调；缺少礼貌性关闭 RPC 本身不证明资源泄漏。

不以潜在日志噪声为由，把有界取消替换成可能继续等待服务端的关闭握手，也不为此引入连接池。若将来确有连接泄漏，应以连接、goroutine 或服务端资源证据定位，而不是以没有 ConnectClose 作为等价证明。

### 不在内存安全目标恢复失败时直接 resume

两次 requested-size 写入之间可能遗留设备容量目标。直接恢复 vCPU 可能使 guest 实际申请整块设备容量。错误可用性差，不代表恢复执行就是安全的。

保留“失败且无法确认安全目标时保持 Paused”。修复方向是明确展示故障、重试条件及由单一写者设置安全目标的人工恢复步骤。不会添加忽略错误的 force-resume 或失败后自动关闭内存控制再继续运行。

### 不把完整来源重连扩大为业务请求重试框架

状态订阅可重连并重新取快照；run/open、注销及内存写入在断线时可能已经生效。未经幂等协议自动重放，可能重复启动程序或作用于后来的状态。

只恢复观测连接。在途业务请求继续向调用方报告失败或结果未知；不新增全局重试管理器、请求重放队列或通用事务层。

### 不承诺 XDG 多文件同步具有进程崩溃原子性

缓存、图标和桌面文件可能位于不同文件系统，且 applications 目录与其他程序共享。不能通过一次 rename 同时提交这些路径。

本轮修复准备失败提前提交缓存、正常错误路径下部分发布及自有 PNG 泄漏；发布失败需要报告回滚失败。不会为应用索引引入 WAL、数据库或常驻恢复服务。掉电或 SIGKILL 后仍以重新运行 sync-apps 修复自有命名空间。

### 不为 xmlBytes 增加理论上的溢出分支

转换结果达到 uint64 字节范围的边界需要约 16 EiB 的内存大小，远超当前支持的实际 VM 内存设备规模。这里读取的是宿主 libvirt 的 live XML，不是开放给任意输入的通用单位换算接口。

不为这一支持范围之外的数值增加错误分支及专门测试，只在乘法处注释输入来源和规模前提。本项已由 reviewer 撤回，不能作为已修复的审查缺陷计数。如果未来输入边界真的改成任意配置或不可信报文，那是接口前提变化，需要重新审查。

## 验证与变更边界

故障测试使用假驱动、临时 socket 和辅助进程，不注销现有 Windows 用户、不改变现有 VM 电源状态、不启动实际确认窗，也不在本轮自动部署。

已运行 `make check` 并通过：主模块 build/vet/race、独立 GUI 模块 build/vet/race、Windows Rust 目标 Clippy（拒绝警告）及测试二进制交叉构建。交叉构建不等于真实 Windows 执行。

关键回归位置：
- `internal/controller/failure_test.go`：业务错误、执行中取消不熔断；自动失败停止重试；请求 StopDisplay 失败后恰好一次自动重试；FIFO 完成对象检查。
- `internal/controller/source_recovery_test.go`：订阅确认前不查询；确认后补查；丢弃旧连接的查询结果；失败快照不忙循环；内存错误定向清除；Unknown 中止准备且旧结果不能恢复它。
- `internal/adapter/session_recovery_test.go`、libvirt 与内存来源测试：不依赖新 VM 事件重连、空窗期 Unknown、新快照替代旧集合、取消和退出。
- `internal/host/socket_test.go`：异常残留恢复、活跃／非 socket 路径保留、并发恢复仅一个可达所有者。
- `internal/host/catalog_sync_test.go`：准备失败不提前提交、发布失败回滚、自有 PNG 清理、显式图标引用保留和单写者发布。

后续已在真实 Win11 上运行 `windows-agent/tests/token-acl.ps1 -RunAsAdministrator -InteractiveUser rdp-user`，补齐 ACL 验收：指定用户账户读取通过、SYSTEM 任务读取及 SHA-256 比对通过、正确 ACL 校验通过、宽泛 Users 授权及 DENY ACE 被拒绝。测试只使用临时目录／任务，并在 finally 中清理；没有替换生产 token、agent、服务或注销会话。首次实测发现的是测试 fixture 问题：读权限 DENY 会提前阻止读取，SYSTEM 输出文件没有继承调用者权限；已改为可读的 WriteData DENY 以验证显式拒绝分支，并让临时结果继承受限 ACL、原子发布。不能用 Rust token 比较单测代替这一实机验收。

宿主控制器所有权使用持久 `socket.lock`，应用同步使用缓存目录的 `.sync.lock`；这两者是不同资源的单写者约束，不是 Windows 会话归属管理器。不创建 PID 文件。
